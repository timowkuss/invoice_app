# Invoice Recognizer — распознавание товарных накладных для 1С

Desktop-приложение для Windows на PySide6, которое распознает товарные
накладные (фото, скан, PDF) и формирует готовый к импорту в
1С:Предприятие Excel-файл. Основная цель — свести к минимуму ручной
ввод позиций накладной.

## Возможности

- Загрузка накладной с камеры, из PDF или из изображения (jpg, jpeg, png, tiff, bmp)
- **Автоматическое исправление поворота фото на 90°/180°/270°** — частый случай, когда документ сфотографирован "как удобно": для каждой страницы приложение пробует все 4 поворота и по уверенности OCR выбирает правильный, только потом делает основной проход распознавания
- Предобработка изображения: устранение шума, коррекция перспективы, выравнивание наклона, повышение контраста (OpenCV)
- Распознавание текста (EasyOCR, языки RU/EN)
- Автоматическая сборка таблицы товаров **без жестких координат колонок**:
  сначала ищется строка-заголовок с названиями колонок, а если ее нет —
  колонки определяются кластеризацией и классификацией содержимого ячеек
- Устойчивость к реальным особенностям накладных: многоуровневая шапка таблицы
  (объединенные колонки, строка с номерами колонок), колонка "№ п/п", колонка
  "Код"/"Артикул"/"Штрихкод", две колонки цены (базовая и "со скидкой" — берется
  фактическая), раздельные "Сумма с НДС"/"Сумма НДС", рукописные галочки рядом
  с числами
- Автоматическое объединение названий товаров, перенесенных на несколько строк
- Редактируемая таблица результата: правка ячеек, добавление/удаление строк, поиск
- Экспорт в Excel (`openpyxl`) с именем файла `Дата_Время.xlsx` в папку `exports/`
- История обработанных документов в SQLite с возможностью открыть старый Excel-файл
- OCR выполняется в отдельном потоке (`QThread`) — интерфейс не зависает, есть индикатор прогресса
- Настройки: папка экспорта, язык интерфейса, тема (светлая/темная), автооткрытие Excel
- Все ошибки логируются в `logs/app.log`

## Установка и запуск

Требуется Python 3.12+.

```bash
python -m venv venv
venv\Scripts\activate        # Windows
pip install -r requirements.txt
python main.py
```

При первом распознавании EasyOCR скачает и закэширует веса моделей —
это может занять несколько минут, зависит от интернет-соединения.

## Формат Excel-файла

Колонки в порядке экспорта: `Название`, `Артикул`, `Штрихкод`,
`Количество`, `Цена`, `Сумма`, `Единица`. Числовые колонки
(Количество/Цена/Сумма) автоматически приводятся к числовому формату,
если это возможно.

## Архитектура для будущих доработок

Проект специально разбит на независимые слои (`ocr/`, `excel/`,
`database/`, `ui/`), чтобы можно было добавлять новые возможности,
не переписывая существующий код:

1. **Подключение к 1С** — добавить модуль `integrations/onec/` с клиентом
   обмена (например, через OData или COM) и вызывать его из
   `MainWindow._on_export_clicked` вместо/вместе с экспортом в Excel.
2. **Документ "Поступление товаров"** — отдельный сервис в
   `integrations/onec/`, использующий уже готовый список `Product`.
3. **Сканирование штрихкодов** — новый воркер в `ui/workers/`,
   использующий `pyzbar` поверх уже существующего `CameraDialog`.
4. **Веб-камера** — уже реализовано (`ui/dialogs/camera_dialog.py`),
   можно расширить выбором устройства.
5. **AI-поиск и сопоставление товаров с базой 1С** — новый модуль
   `matching/`, использующий эмбеддинги названий товаров, подключаемый
   после `TableParser.parse()`.
6. **Автоматическое сопоставление** — логика в `matching/` возвращает
   `Product` с уже подставленным кодом 1С.
7. **Распознавание поставщика** — расширение `TableParser`/отдельный
   классификатор шапки документа, результат передается в `DocumentRecord.supplier`.
8. **Облачная синхронизация** — заменить/дополнить `DatabaseManager`
   удаленным API поверх того же интерфейса методов.
9. **Многопользовательский режим** — вынести `DatabaseManager` на
   серверную СУБД (PostgreSQL) за REST-фасадом.
10. **REST API** — обернуть `ocr/pipeline.py` и `excel/exporter.py`
    в FastAPI-сервис, переиспользуя всю бизнес-логику без изменений.

## Лицензия

Внутренний проект. Использование и модификация — по усмотрению владельца.

## Редактирование строк в веб-версии

После распознавания накладной кнопка «Добавить строку» позволяет выбрать
товар из каталога магазина, указать количество и цену. Кнопка «Удалить»
рядом со строкой запрашивает подтверждение удаления. Можно удалить все
строки и затем заполнить накладную заново.

После добавления, изменения или удаления строки накладная возвращается
на проверку. Итог и счётчики пересчитываются, изменения сохраняются в
истории. Для Excel-экспорта необходимо снова нажать «Всё проверено»;
пустую накладную подтвердить нельзя. Перед добавлением, удалением или
выбором другого товара сохраните изменения количества и цены.

## Аккаунты и восстановление пароля

Самостоятельная регистрация отключена. При первом запуске владелец сервиса
создаётся из `ADMIN_EMAIL` и `ADMIN_PASSWORD` в `.env`. Владелец добавляет
магазин, выбирает его и создаёт аккаунты клиентов в разделе **Аккаунты**.
Клиенты входят только по email и не могут создавать другие аккаунты.

Для кнопки «Забыли пароль?» настройте SMTP-переменные из `.env.example`:
`SMTP_HOST`, `SMTP_PORT`, `SMTP_USERNAME`, `SMTP_PASSWORD`, `SMTP_FROM` и
`SMTP_STARTTLS` (либо `SMTP_SSL=true`). Ссылка из письма действует 30 минут
и может быть использована один раз. `WEB_URL` должен содержать публичный адрес
сайта, чтобы ссылка из письма открывалась у клиента.

## Telegram-бот и веб-приложение

Бот принимает накладные в личном чате и сохраняет их в общей базе магазина.
Распознавание выполняет очередь веб-приложения. Бот не использует старую
SQLite-историю desktop-версии и не экспортирует непроверенные OCR-строки.

### Запуск

1. Установите зависимости: `pip install -r requirements-telegram.txt`.
2. Создайте `.env` в корне проекта. Задайте `TELEGRAM_TOKEN` от BotFather,
   `MISTRAL_API_KEY`, случайный `SECRET_KEY` и `WEB_URL` — публичный HTTPS-адрес
   сайта. Не добавляйте `.env` в Git. `localhost` недоступен сотрудникам с телефона.
3. У сайта и бота должны совпадать `DATABASE_URL` и `DATA_DIR`: база и папка
   исходников общие. При разных серверах нужна общая файловая система для
   `DATA_DIR`. Для локального теста без `DATABASE_URL` используется SQLite.
4. Запустите сайт с обработчиком очереди:
   `python -m uvicorn api.main:app --host 0.0.0.0 --port 8000`.
   `OCR_WORKER=true` (по умолчанию). Если он выключен, накладные останутся в очереди.
5. В другом процессе запустите `python run_telegram.py`.
   Используется long polling: один процесс бота на один токен. Если токен
   ранее использовался с webhook, сначала отключите webhook в вашей конфигурации.
   Бот сам не удаляет webhook и не сбрасывает ожидающие сообщения.

### Привязка сотрудника

- Владелец сервиса создаёт сотруднику аккаунт нужного магазина на сайте.
- Сотрудник отправляет `/id` боту в личном чате и сообщает ID администратору.
- Владелец сервиса открывает **Аккаунты → Telegram → Подключить** у сотрудника,
  проверяет переданный ID и сохраняет привязку. Привязка даёт доступ к накладным
  магазина; не используйте ID, полученные из непроверенных источников.
- Там же можно изменить привязку или отключить Telegram. Один Telegram ID
  нельзя назначить двум аккаунтам. Пароль сайта не передаётся боту.

### Обработка

Отправьте фото, JPG, PNG, WebP или PDF до 20 МБ (PDF до 30 страниц).
Один файл считается одной накладной; несколько страниц отправляйте одним PDF.
Бот сообщает номер документа и даёт ссылку на него. После входа на сайте
открывается именно эта накладная. Проверьте строки, подтвердите документ и
скачайте Excel на сайте.

Команды: `/history` — пять последних накладных магазина, `/status 12` — статус
документа №12, `/retry 12` — повтор после ошибки. Автоматического отдельного
уведомления о завершении пока нет: используйте `/status` или страницу документа.
Повтор того же файла не создаёт копию. Общие лимиты загрузки и повторов OCR
действуют и для сайта, и для бота. Непривязанные/отключённые пользователи,
групповые чаты и чужие магазины не получают доступ к документам.

Владелец сервиса видит раздел **Статистика** со сводкой Mistral по всем
магазинам: число запросов, ошибки, страницы, длительность и расчётную стоимость.
Для расчёта задайте актуальный тариф в `MISTRAL_COST_PER_1000_PAGES_USD`.

Проверки без реального Telegram и платного OCR:
`pip install pytest` и `python -m pytest -q`.
Тесты Telegram подменяют только сетевой транспорт; работа с базой и API проверяется реально.
